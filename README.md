# 📚 LibCode-2

Курсова робота (2 курс)

## 📖 Огляд

> Цей проєкт є курсовою роботою, розробленою на мові програмування **C++ 20** з використанням бази даних **PostgreSQL**. Система призначена для автоматизації бібліотечного фонду міста та забезпечує ефективне управління бібліотечними ресурсами: книгами, читачами, статистикою відвідуваності тощо.

Інтерфейс розроблено для двох типів користувачів: **бібліотекарів**, які здійснюють основну діяльність з обробки даних, та **адміністраторів**, які мають повний доступ до функцій керування системою.

## 🗄 Встановлення PostgreSQL

1. Завантаж PostgreSQL з офіційного сайту:
   👉 **[postgresql.org/download/windows](https://www.postgresql.org/download/windows/)**

2. Під час встановлення запам'ятай пароль користувача `postgres` — він знадобиться далі.

3. Після встановлення додай шлях до `bin` у системні змінні:
   - Знайди шлях, наприклад: `D:\Programs\Postgres\bin`
   - Відкрий: `Пуск → Змінні середовища → Змінні середовища системи`
   - У розділі **Системні змінні** знайди `Path` → **Редагувати** → **Створити**
   - Встав шлях і натисни **OK** у всіх вікнах

## 🗃 Відновлення бази даних

Файл бекапу знаходиться у папці `database/` репозиторію.

Відкрий **PowerShell** і виконай по черзі:

```powershell
# 1. Створити базу даних
psql -U postgres -c 'CREATE DATABASE "Library"'

# 2. Перейти до папки з бекапом (вкажи свій шлях до репо)
cd "D:\Dокументи\Мої програми\Курсова 2\database"

# 3. Відновити базу даних з бекапу

	# Відновлення з SQL
psql -U postgres -d "library" -f "library.sql"

	# Відновлення з дампу
pg_restore -U postgres -d "library" -c "library.dump"
```

> При виконанні команд система може запитати пароль користувача `postgres`.

## ⚙️ Налаштування підключення до БД (.env)

Логін і пароль від PostgreSQL **не зашиті в код** — застосунок читає їх зі
змінних середовища / файлу `.env` за допомогою класу `EnvConfig`
(`EnvConfig.cpp` / `EnvConfig.h`), який лежить у `Library/` поруч із
`main.cpp`.

### Як це працює (порядок пошуку значень)

`EnvConfig::load()` викликається на самому старті `main()` і шукає
конфігурацію в такому порядку:

1. **`Library/.env`** — твій особистий файл із реальними даними.
2. Якщо `.env` не створено — **`Library/.env.example`** (шаблон, що лежить
   у репозиторії) використовується автоматично, тож застосунок все одно
   запуститься "з коробки", без додаткових кроків.
3. Для кожного окремого ключа (`DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`,
   `DB_PASSWORD`) **справжня змінна середовища ОС** (якщо вона задана) має
   пріоритет над обома файлами — зручно для CI/CD чи запуску без файлів
   поруч з `.exe`.

Тобто працюючий (хай і з даними-заглушками з прикладу) застосунок є одразу
після клонування репозиторію — і при цьому реальний пароль ніколи туди не
потрапляє.

### Як підключитись своїми даними

1. Скопіюй приклад у робочий файл (в тій самій папці `Library/`, поруч із
   `main.cpp`, — саме там за замовчуванням знаходиться робоча директорія
   при запуску з Visual Studio):

   ```powershell
   cd Library
   copy .env.example .env
   ```

2. Відкрий `Library/.env` і встав свій реальний пароль від користувача
   `postgres` (та за потреби зміни хост / порт / назву БД / логін):

   ```env
   DB_HOST=localhost
   DB_PORT=5432
   DB_NAME=library
   DB_USER=postgres
   DB_PASSWORD=ТУТ_ТВІЙ_ПАРОЛЬ
   ```

3. Файл `.env` додано до `.gitignore` і **ніколи не потрапляє в git** — у
   репозиторії лишається лише `.env.example` без реальних даних.

> ⚠️ `DB_PASSWORD` у `.env.example` — це лише заглушка (`your_password_here`).
> Якщо не створити `.env`, застосунок стартує з неї і, найімовірніше,
> отримає помилку авторизації від PostgreSQL (це очікувано — див. пункт 2).
> Якщо ж і в `.env`, і в `.env.example`, і в системному середовищі
> `DB_PASSWORD` виявиться порожнім рядком, застосунок одразу виведе
> повідомлення про помилку в консоль і завершиться, не намагаючись
> підключитися до БД з порожнім паролем.

## 🚀 Встановлення та розгортання

Для збірки проєкту на Windows рекомендується використовувати менеджер пакетів **vcpkg**, встановлений на диск **D:** для уникнення конфліктів із правами доступу на системному диску.

### 1. Налаштування vcpkg

Відкрийте **PowerShell (Адміністратор)** та виконайте:

```powershell
# Створення робочої директорії
d:
mkdir D:\Programs
cd D:\Programs

# Клонування та збірка менеджера пакетів
git clone https://github.com/Microsoft/vcpkg.git
cd vcpkg
.\bootstrap-vcpkg.bat

# Налаштування системних змінних оточення
[System.Environment]::SetEnvironmentVariable("VCPKG_ROOT", "D:\Programs\vcpkg", "User")
[System.Environment]::SetEnvironmentVariable("VCPKG_DEFAULT_BINARY_CACHE", "D:\Programs\vcpkg\archives", "User")
```

### 2. Встановлення залежностей

```powershell
.\vcpkg install ftxui:x64-windows
.\vcpkg install libpqxx:x64-windows
```

### 3. Інтеграція з Visual Studio

```powershell
.\vcpkg integrate install
```

## 🏗 Архітектура

Проєкт побудований на **трирівневій архітектурі** (інтерфейс → логіка → доступ до БД) та використовує наступні патерни проєктування:

| Патерн               | Клас(и)                                      | Призначення                                          |
| -------------------- | -------------------------------------------- | ---------------------------------------------------- |
| **Abstract Factory** | `PostgresFactory`, `IDBConnect`, `IDBOutput` | Створення об'єктів для підключення до PostgreSQL     |
| **Adapter**          | `ResultAdapter`                              | Конвертація `pqxx::result` у формат `PostgresOutput` |
| **Factory Method**   | `MenuCreator`, `AdminMenu`, `LibrarianMenu`  | Динамічне створення меню залежно від ролі            |
| **Singleton**        | `Logger`                                     | Централізоване логування подій                       |
| **Facade**           | `ApplicationCoordinator`                     | Координація взаємодії між компонентами               |
| **Decorator**        | `ConsoleUtilsDecorator`                      | Стилізація консольного виведення                     |
| **Proxy**            | `AuthorizationProxy`                         | Контроль доступу та логування авторизації            |

## 📝 Функціонал

### 👤 Бібліотекар

Головне меню бібліотекаря містить такі пункти:

- **Information about books** — перегляд повного переліку книг (назва, автор, жанр, видавництво, рік, ISBN) на основі `JOIN` з таблицями `book_details`, `book_authors`, `authors`
- **Information about readers** — перегляд читачів та їхньої категорії (`JOIN` з `category_details`, `categories`)
- **Information about visits** — перегляд історії відвідувань (`JOIN` таблиць `visits`, `readers`, `libraries`, `books`)
- **Most popular books** — рейтинг книг за кількістю видач (`GROUP BY` + `COUNT` + `ORDER BY`)
- **Add book** — додавання нової книги; автор створюється автоматично, якщо ще не існує в БД; жанр, видавництво, рік і ISBN — необов'язкові
- **Add reader** — додавання читача з вибором категорії: **школяр**, **студент**, **дошкільник** або **науковець**, кожна з яких має власний набір додаткових полів (заклад, спеціальність, номер школи, назва садочка, галузь дослідження)
- **Add visit** — реєстрація видачі книги читачеві у конкретній бібліотеці (форма з випадаючими списками наявних читачів, бібліотек і книг)
- **Exit** — вихід із системи

### 🔧 Адміністратор

Головне меню адміністратора містить такі пункти:

- **Information about libraries** — перелік усіх бібліотек фонду
- **Information about librarians** — перелік бібліотекарів з прив'язкою до конкретної бібліотеки та графіком роботи (дні й години зміни)
- **Add user** — створення нового облікового запису системи (логін, пароль, роль); для ролі бібліотекаря додатково вказуються ПІБ, бібліотека та графік роботи
- **System statistics** — відкриває системний журнал (`log.txt`) у Блокноті для перегляду історії дій і подій застосунку
- **Log out** — вихід із системи

### ⚙️ Системні можливості

- **Авторизація з розмежуванням прав доступу** — після входу роль користувача (`admin`/`librarian`) визначається запитом до БД, і система формує відповідне меню
- **Обмеження часу доступу (Proxy)** — `AuthorizationProxy` дозволяє авторизацію лише в проміжку **з 07:00 до 16:00**; поза цим вікном спроба входу відхиляється, а подія фіксується в журналі
- **JOIN-запити до БД** — усі звітні розділи (книги, читачі, відвідування, статистика) будуються на `JOIN`-запитах до кількох пов'язаних таблиць
- **Автоматичне збереження результатів** — вивід будь-якого звітного запиту форматується (`PostgresOutput` + `ResultAdapter`) і записується у файл `output.txt`, який одразу відкривається в Блокноті
- **Журналювання дій системи** — усі ключові події (вхід, помилки SQL, створення об'єктів, дії користувача) фіксуються з таймстампом у `log.txt` через `Singleton Logger`
- **Розширюваність на інші СУБД** — доступ до БД абстраговано через `Abstract Factory` (`IDBFactory`, `IDBConnect`, `IDBOutput`), тож підключення нової СУБД не вимагає змін у бізнес-логіці

> ⚠️ **Примітка:** функції автоматичного відкриття `output.txt` та `log.txt` у Блокноті (`CreateProcessW`/`notepad.exe`) реалізовані лише для **Windows**. На інших платформах ці дії пропускаються з відповідним записом у журналі.

## 📦 Готовий білд (Release)

Не хочеш збирати проєкт самостійно? У розділі **[Releases](../../releases)** доступний готовий білд для Windows x64.

> ⚠️ **Важливо:** застосунок — не один файл. `Library.exe` динамічно лінкується з бібліотеками `libpqxx` і `PostgreSQL`, тож для запуску потрібні **всі файли разом**, з тієї самої папки `x64/Release`:
>
> | Файл                  | Призначення                                                                |
> | --------------------- | -------------------------------------------------------------------------- |
> | `Library.exe`         | сам застосунок                                                             |
> | `pqxx.dll`            | обгортка libpqxx для роботи з PostgreSQL                                   |
> | `LIBPQ.dll`           | клієнтська бібліотека PostgreSQL (libpq)                                   |
> | `libssl-3-x64.dll`    | OpenSSL — шифрування з'єднання до БД                                       |
> | `libcrypto-3-x64.dll` | OpenSSL — криптографічні примітиви                                         |
> | `Library.pdb`         | символи налагодження (необов'язковий, для дебагу)                          |
> | `.env.example`        | шаблон конфігурації БД — скопіюй у `.env` і встав свій пароль (див. нижче) |
>
> Завантаж **усі** файли з релізу в одну папку — без `.dll` застосунок не запуститься (Windows видасть помилку про відсутню бібліотеку).

1. Встанови **PostgreSQL** та віднови базу даних — див. розділи [🗄 Встановлення PostgreSQL](#-встановлення-postgresql) та [🗃 Відновлення бази даних](#-відновлення-бази-даних) вище.
2. Завантаж усі файли релізу (`Library.exe`, `.dll`, `.env.example`, перелічені вище) з останнього релізу в одну папку.
3. У тій самій папці скопіюй `.env.example` у `.env` і встав свій реальний пароль від `postgres` (див. [⚙️ Налаштування підключення до БД (.env)](#️-налаштування-підключення-до-бд-env)). Без `.env` (або без змінних середовища `DB_*`) застосунок або підключиться з паролем-заглушкою з `.env.example`, або, якщо й там порожньо, одразу завершиться з повідомленням про відсутній `DB_PASSWORD` — зашитого в код пароля більше немає.
4. Запусти `Library.exe`.
5. Вхід у систему дозволений лише **з 07:00 до 16:00** — це навмисне обмеження (`AuthorizationProxy`), а не помилка застосунку.
6. Файли `log.txt` та `output.txt` створюються поруч із `.exe` під час роботи програми.
